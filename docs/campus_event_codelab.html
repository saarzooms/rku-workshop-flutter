Chapter 1 Est. 20 min Workshop Overview

Build a Campus Event & Attendance Management System

Learning Objective: Understand the real-world problem, system scope, user roles, and full-stack architecture you will build over this 8–10 hour workshop.

Why are we doing this? Universities run dozens of seminars, workshops, and hackathons every semester. Paper attendance sheets are slow and easy to forge. You will build an end-to-end digital solution with Flutter, PHP 8, MySQL, QR Codes, and Firebase Cloud Messaging (FCM).

What You Will Build

  • Student Experience: Discover events, search & filter by category, register with capacity checks, scan organizer QR codes to mark attendance, and receive push notifications.
  • Organizer Experience: Create/edit/cancel events, view registration counts, generate time-limited attendance QR codes, view attendance reports, and notify registrants.
  • Admin Experience: Seeded campus administrator account with an overview dashboard of users, events, registrations, and attendance.

Technologies Used

LayerTechnologyWhy We Chose It
Mobile AppFlutter 3.x (Dart, Material 3)Fast UI iteration with Hot Reload and strong typing.
Backend APIPHP 8.x (PDO, JSON REST)Zero-framework clarity, easy local setup, portable hosting.
DatabaseMySQL 8 / MariaDBRelational integrity with Foreign Keys and Unique Constraints.
Push NotificationsFirebase Cloud MessagingReliable Android push delivery without making Firebase our primary DB.

Chapter 3 Est. 30 min

Requirement Analysis (Before Coding)

Learning Objective: Translate campus needs into clear Functional Requirements, Non-Functional Requirements, and MVP scope.

Why before coding? Writing code without requirements causes rework, missing database constraints, and insecure shortcuts. See full details in docs/requirements.md.

User Roles & Core Stories

  • Student: "As a student, I want to register for an event once and scan an organizer's QR code so my attendance is recorded."
  • Organizer: "As an organizer, I want to generate a 15-minute expiring QR code so students cannot share static screenshots."
  • Admin: "As an admin, I want to view campus-wide event and attendance statistics."

Non-Functional Security Rules

  • Hash passwords with password_hash(..., PASSWORD_BCRYPT).
  • Use PDO prepared statements everywhere to prevent SQL injection.
  • Prevent duplicate registrations and duplicate attendance at both the API and MySQL UNIQUE constraint levels.

System Architecture, Database & API Design

Learning Objective: Understand how Flutter (MVVM + Repository), PHP (Router + Middleware + Controllers + Repositories), MySQL, and FCM fit together.

High-Level Architecture

flowchart LR UI["Flutter UI (Views)"] --> VM["ViewModels (Provider)"] --> REPO["Repositories"] --> API["PHP 8 REST API"] API --> DB[("MySQL Database")] API --> FCM["FCM HTTP v1"] FCM --> UI

Entity-Relationship Overview

Key tables in campus_event_api/database/database.sql:

  • users → events (organizer_id)
  • event_categories → events (category_id)
  • events + users → event_registrations (UNIQUE (event_id, user_id))
  • event_registrations → attendance (UNIQUE (registration_id))
  • events → attendance_qr_tokens (SHA-256 hashed, time-limited)
  • users → user_sessions & device_tokens

Consistent JSON Response Envelope

Sprint 2: Build the PHP 8 REST API & MySQL Database

1. Import Schema & Start Server

cd campus_event_api

2. Security Highlights in AuthController.php

  • Public /api/auth/register always forces role = 'student'.
  • Passwords are hashed with password_hash($password, PASSWORD_BCRYPT).
  • Opaque 64-char hex bearer tokens are hashed with hash('sha256', $token) before storing in user_sessions.
Expected Output: Visiting http://localhost:8000/api/health returns {"success":true,"message":"Campus Event API is running",...}.

Sprints 3 & 4: Integrate Flutter with PHP

Learning Objective: Trace how data flows from a button tap → ViewModel → Repository → ApiClient → PHP → MySQL and back.

Networking & Token Storage

  • lib/core/constants/api_constants.dart uses http://10.0.2.2:8000 for the Android Emulator and supports --dart-define=API_BASE_URL=... for physical devices.
  • lib/core/network/api_client.dart automatically reads the bearer token from FlutterSecureStorage and attaches Authorization: Bearer <token>.

Data Flow Example: Event Registration

  1. Student taps Register Now in EventDetailScreen.
  2. RegistrationViewModel.registerForEvent() sets isSubmitting = true.
  3. RegistrationRepository calls POST /api/events/{id}/register.
  4. PHP checks event status, capacity, and duplicate registration, then inserts into event_registrations.

Sprint 5: Secure QR Code Attendance

Learning Objective: Implement time-limited QR generation and server-side attendance verification.

Why not static QR codes? A static QR code containing only event_id=1 can be photographed and shared with absent students. Our PHP backend generates a random CAMPUS_QR_... token, stores its SHA-256 hash in attendance_qr_tokens with a 15-minute expiry, and verifies registration + duplicate attendance on the server.

Key Files

  • campus_event_api/app/Controllers/AttendanceController.php (generateQr, verify, eventReport)
  • campus_event_app/lib/features/attendance/views/qr_generate_screen.dart (qr_flutter)
  • campus_event_app/lib/features/attendance/views/qr_scan_screen.dart (mobile_scanner + manual emulator paste box)
Chapter 11 Est. 45 min

Sprint 6: Firebase Cloud Messaging (FCM)

Learning Objective: Register Android device tokens with PHP and send event notifications via FCM HTTP v1.

Setup Steps

  1. Create a Firebase project and register Android app ID edu.campus.campus_event_app.
  2. Download google-services.json into campus_event_app/android/app/.
  3. Generate a Firebase Service Account JSON and place it in campus_event_api/storage/firebase-service-account.json (never inside public/ or Flutter!).
  4. Update FCM_PROJECT_ID and FCM_SERVICE_ACCOUNT_PATH in campus_event_api/.env.
Optional Alternatives: Firebase Auth & Cloud Firestore

In a serverless-only architecture, Firebase Auth could replace PHP sessions and Firestore could replace MySQL. We keep PHP + MySQL as our primary stack so you master relational schemas, SQL constraints, and REST API security.
