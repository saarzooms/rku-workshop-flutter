Scenario: Imagine the Dean of Student Affairs at your university hires you to replace their manual event workflow. Here are the exact pain points and requirements they give you:

D. Backend & Notifications: Why PHP 8 + FCM (Notifications Only)?

  • Plain PHP 8 vs Laravel / Node.js: Frameworks like Laravel add hundreds of files and magic abstractions. Plain PHP 8 with PSR-4 autoloading and PDO lets beginners see every single step of an HTTP request, SQL query, and JSON response.
  • PHP Sessions + FCM vs Firebase Auth + Firestore: We use Firebase only for Firebase Cloud Messaging (FCM) push delivery, keeping user accounts, passwords, and attendance rules under your full control in PHP + MySQL. (Chapter 11 also explains how Firebase Auth/Firestore could be used as an optional alternative.)

Checkpoint

  2. Why do we use Firebase only for push notifications instead of storing all data in Firestore?
Reveal Checkpoint Answers

1. Connecting a mobile app directly to MySQL would expose database credentials inside the APK, allowing anyone to decompile the app and delete or steal all data. A PHP REST API enforces authentication, validation, and role rules on the server.

1. Why MVVM? (And Not MVC, MVP, or Raw Widgets)

Beginners often write http.get(...) directly inside a button's onPressed callback. That works for a 1-screen demo, but in a 10-screen app it creates spaghetti code that is impossible to test or reuse. Here is how common architectures compare in Flutter:

ArchitectureHow It WorksWhy Chosen / Not Chosen
Spaghetti (Logic in Widgets)http calls & setState inside build() / StatefulWidgetFast for 1 screen, breaks down immediately when sharing auth or event data across tabs.
MVC / MVPController/Presenter holds a direct reference to the View interfaceFlutter widgets are immutable and rebuilt declaratively, making Presenter↔View interfaces awkward.
Full Clean ArchitectureDomain UseCases + Entities + DTOs + MappersGreat for 50+ developer enterprise teams, but too much boilerplate for an 8–10 hour workshop.
MVVM + Repository (Chosen)Views observe ViewModels (Riverpod Notifier); ViewModels call RepositoriesMatches Flutter's reactive UI natively, keeps widgets pure, and is easy to unit-test.

Role of the Repository Layer vs. Role of Riverpod

  • Role of the Repository (EventRepository, AuthRepository): The Repository is the translator and coordinator. Your ViewModel should never care whether data came from a REST API, a local cache, or a mock test file. The Repository calls Service (raw HTTP), converts raw JSON maps into typed Dart models (EventModel), and handles token persistence.
  • Role of Riverpod (flutter_riverpod): Riverpod is the wiring and state-delivery engine.
    • Provider creates and shares singletons like apiClientProvider and eventRepositoryProvider.
    • NotifierProvider holds your ViewModel (EventViewModel) and its immutable state (EventState: isLoading, events, errorMessage).
    • ref.watch(...) automatically rebuilds only the widgets listening to that state; ref.read(...notifier) triggers actions like login() or loadEvents().

2. How to Find Database Tables & Generate an ER Diagram

Beginners often wonder: "How do engineers know which tables to create?" Follow this 5-step method on any project:

  1. Step 1 — Underline the Nouns in Requirements: Read Chapter 1 & 3 and list the core real-world "things": User, Category, Event, Registration, QR Token, Attendance, Device Token, Notification, Session. Each major noun becomes a table!
  2. Step 2 — Assign a Primary Key (PK) & Attributes: Every table gets an id PK plus its descriptive columns (e.g., events has title, venue, start_time, max_capacity).
  3. Step 3 — Identify Relationships & Resolve Many-to-Many (M:N):
    • One user (organizer) can create many events → 1:N (add organizer_id FK to events).
    • One user (student) can register for many events, and one event has many students → M:N! Relational databases cannot store a list inside one cell, so we create a junction table: event_registrations.
    • One registration can have at most one attendance record → 1:0..1.
  4. Step 4 — Add UNIQUE Constraints for Business Rules: Adding UNIQUE (event_id, user_id) on event_registrations and UNIQUE (registration_id) on attendance makes duplicate registrations and duplicate attendance physically impossible in MySQL.
  5. Step 5 — Draw the ER Diagram: Connect PKs to FKs with lines so anyone can read the data model at a glance.

3. Why Bearer Tokens? (And Not Cookies, Basic Auth, or Stateless JWTs)

HTTP is stateless: every API request arrives fresh, so the server needs a secure way to know who is calling. Why not other methods?

Auth MethodHow It WorksWhy Chosen / Not Chosen
HTTP Basic AuthSends email:password on every API callInsecure if stored on phone; cannot revoke a single device without changing the user's password.
PHP Session CookiesBrowser stores PHPSESSID cookie automaticallyGreat for websites, awkward for native mobile HTTP clients (http package) and cross-domain APIs.
Stateless JWTSelf-contained signed JSON tokenHard to revoke immediately on logout or account ban without adding a server blocklist anyway; requires extra JWT library.
Opaque Bearer Token (Chosen)Random 64-hex token; SHA-256 hash stored in user_sessionsZero external libraries, instant logout/revocation (is_revoked = 1), encrypted on phone via FlutterSecureStorage.

Checkpoint

  1. Why do we create a junction table event_registrations instead of storing a comma-separated list of event IDs inside users?
  2. Why does PHP store hash('sha256', $token) in user_sessions instead of the raw token?
Reveal Checkpoint Answers

1. Comma-separated lists violate First Normal Form (1NF): you cannot enforce FOREIGN KEY integrity, prevent duplicates with UNIQUE, or efficiently run COUNT(*) / JOIN queries for attendance reports.

2. If someone ever obtains a read-only copy of the database backup, hashed tokens cannot be used to impersonate logged-in users.

1. What is Agile & Why Are We Using It?

Agile is a software development mindset where you build a product in small, working increments instead of trying to build the entire application all at once. After each small increment, you test it, verify it works end-to-end, and only then move to the next feature.

ApproachHow It WorksBenefits & Drawbacks
Waterfall (Sequential)Finish 100% of design → 100% of backend → 100% of Flutter UI → test at the very endHigh risk: if an API response format doesn't match what Flutter needs, you discover it too late and rewrite dozens of files.
Ad-Hoc ("Just Start Coding")No plan, jump between screens and SQL tables randomlyLeads to broken foreign keys, missing auth checks, and half-finished features.
Agile / Scrum (Chosen)Break the app into small, time-boxed Sprints; each Sprint delivers a tested, working featureEarly feedback, lower bug risk, clear progress, and a working demo at the end of every stage.

2. Key Agile & Scrum Terms for Beginners

  • Scrum: A popular, lightweight framework for practicing Agile. It organizes work into fixed-length cycles called Sprints.
  • Product Backlog: The master, prioritized list of all features the app needs (e.g., Login, Event List, QR Attendance, Push Notifications).
  • User Story: A backlog item written from the user's perspective: "As a [Student], I want [to scan a QR code], so that [my attendance is recorded]."
  • Sprint: A focused, time-boxed iteration (typically 1–2 weeks in industry, or 45–60 minutes per module in our 8–10 hour workshop) with a clear Sprint Goal.
  • Sprint Planning: Selecting which backlog items fit into the current Sprint and breaking them into concrete coding tasks.
  • Sprint Review: Running and demonstrating the working feature (e.g., testing an API in Postman or running the Flutter screen) before starting the next Sprint.

3. How Do We Divide This Project Into Sprints?

You cannot build features in random order—features have dependencies. Use these 4 rules to slice any project into Sprints:

  1. Architecture & Foundation First (Sprints 0–2): Design the database and API contract (Sprint 0), build the navigable Flutter UI shell (Sprint 1), and stand up the PHP + MySQL authentication API (Sprint 2).
  2. Follow Data Dependencies (Sprints 3–5): Students cannot register for events until events exist (Sprint 3 → Sprint 4), and cannot mark QR attendance until registrations exist (Sprint 4 → Sprint 5).
  3. Isolate External Services (Sprint 6): Integrate Firebase Cloud Messaging after the core app already works, so external credentials never block core testing.
  4. Harden & Ship (Sprint 7): Dedicate the final sprint to automated tests, Postman negative cases, and signed release builds.

4. What is Definition of Done (DoD)?

In beginner projects, developers often say "I'm done!" right after typing the code—even if it hasn't been tested, crashes on empty input, or breaks architecture rules. A Definition of Done (DoD) is a shared quality checklist that every Sprint must pass before it counts as complete:

Our Workshop Definition of Done (DoD):
  1. Architecture: Code follows MVVM + Repository + Riverpod (Flutter) and Controller + Repository (PHP).
  2. Static Analysis: flutter analyze and php -l pass with zero errors.
  3. Functional Verification: Both happy paths (200/201) and error cases (401/403/409/422) are verified.
  4. Tests: Unit/widget tests in flutter test pass.
  5. Security & Docs: No hardcoded secrets; documentation matches the implemented code.

B. Why Monorepo? Architectural Justification

CriteriaMulti-Repo (Polyrepo)Unified Monorepo (Chosen)Justification for Our Campus Platform
Atomic Changes Requires coordinating 2–3 PRs across separate repos when an API schema changes. 1 Pull Request updates the PHP endpoint, the Flutter Riverpod repository, and the Postman collection simultaneously. Prevents "API updated but mobile app broken" desynchronization.
API Contract Sync Frontend team might test against stale API docs in another repo. The API specification (docs/api_documentation.md), PHP routes, and Flutter ApiClient live side-by-side. Code reviews catch contract mismatches before code is merged.
Onboarding & Setup New engineers must find, clone, and configure multiple repositories with mismatched branches. Single git clone provides the complete full-stack environment immediately. Crucial for fast developer onboarding and beginner workshop participants.
Automated CI/CD Requires complex webhook triggers across repositories. GitHub Actions can run frontend tests, backend tests, and lint checks in parallel on a single commit. Guarantees that no merge breaks either half of the system.

C. Company Git Branching Strategy (GitFlow / GitHub Flow)

In enterprise engineering, developers never commit directly to the main branch. We follow GitHub Flow with protected branches:

  • main: Production-ready code. Always deployable. Protected by branch rules requiring at least 1 approved Pull Request review and passing CI.
  • develop (optional for staging): Integration branch where completed sprints meet before release tagging.
  • feature/<sprint-feature>: Short-lived developer branches (e.g., feature/sprint-5-qr-attendance, feature/auth-riverpod). Created from main, submitted via Pull Request, reviewed, and merged using "Squash and Merge" to keep a clean commit history.
  • fix/<bug-name>: Focused patch branches resolving QA or testing failures.

declare(strict_types=1);

namespace App\Config;

final class Env
{
    private static array $values = [];

    public static function load(string $path): void
    {
        if (!is_file($path)) return;
        $lines = file($path, FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES);
        if ($lines === false) return;

        foreach ($lines as $line) {
            $trimmed = trim($line);
            if ($trimmed === '' || str_starts_with($trimmed, '#')) continue;
            $parts = explode('=', $trimmed, 2);
            if (count($parts) === 2) {
                $key = trim($parts[0]);
                $val = trim($parts[1], " \t\n\r\0\x0B\"'");
                self::$values[$key] = $val;
                if (getenv($key) === false) putenv("$key=$val");
            }
        }
    }

    public static function get(string $key, ?string $default = null): ?string
    {
        if (array_key_exists($key, self::$values)) return self::$values[$key];
        $envVal = getenv($key);
        return $envVal !== false ? (string) $envVal : $default;
    }
}

campus_event_api/app/Helpers/Router.php 
<?php

declare(strict_types=1);

namespace App\Helpers;

final class Router
{
    private array $routes = [];

    public function add(string $method, string $pattern, callable|array $handler, array $middleware = []): void
    {
        $regex = preg_replace('#\{([a-zA-Z_][a-zA-Z0-9_]*)\}#', '(?P<$1>[^/]+)', $pattern);
        $this->routes[] = [
            'method' => strtoupper($method),
            'regex' => '#^' . $regex . '$#',
            'handler' => $handler,
            'middleware' => $middleware,
        ];
    }

    public function dispatch(string $method, string $path): void
    {
        $method = strtoupper($method);

        foreach ($this->routes as $route) {
            if ($route['method'] !== $method) continue;
            if (preg_match($route['regex'], $path, $matches)) {
                $params = [];
                foreach ($matches as $key => $value) {
                    if (is_string($key)) $params[$key] = $value;
                }

                $context = ['params' => $params, 'user' => null];
                foreach ($route['middleware'] as $mw) {
                    $context = $mw($context);
                }

                $handler = $route['handler'];
                if (is_array($handler)) {
                    [$class, $action] = $handler;
                    (new $class())->$action($context);
                    return;
                }
                $handler($context);
                return;
            }
        }

        Response::error('Endpoint not found', 404);
    }
}

Explanation: This lightweight router turns route patterns like /api/events/{id} into named regular expression capture groups (?P<id>[^/]+), extracts $context['params']['id'], runs middleware sequentially, and dispatches to [Controller::class, 'method'] without needing an external routing library.

namespace App\Middleware;

final class AuthMiddleware
{
    public static function extractBearerToken(): ?string
    {
        $header = $_SERVER['HTTP_AUTHORIZATION'] ?? $_SERVER['REDIRECT_HTTP_AUTHORIZATION'] ?? '';
        if ($header === '' && function_exists('apache_request_headers')) {
            $headers = apache_request_headers();

        }
        if (preg_match('/Bearer\s+(.+)$/i', $header, $matches)) {

    {

                $user = (new UserRepository())->findBySessionToken($token);
                if ($user !== null && (int) $user['is_active'] === 1) {
                    $context['user'] = $user;
                    $context['token'] = $token;
                }
            }
            return $context;
        };
    }

    public static function requireAuth(array $allowedRoles = []): callable
    {
        return function (array $context) use ($allowedRoles): array {
            $token = self::extractBearerToken();
            if ($token === null) Response::error('Authentication required', 401);

            $user = (new UserRepository())->findBySessionToken($token);
            if ($user === null) Response::error('Invalid or expired session token', 401);
            if ((int) $user['is_active'] !== 1) Response::error('Account is deactivated', 403);

            if ($allowedRoles !== [] && !in_array($user['role'], $allowedRoles, true)) {
                Response::error('Forbidden: insufficient permissions', 403);
            }

            $context['user'] = $user;
            $context['token'] = $token;
            return $context;
        };
    }

final class AuthController

    public function register(array $context): void
    {
        $input = Response::readJsonBody();
        $errors = Validator::requireFields($input, ['full_name', 'email', 'password']);
        $email = strtolower(trim((string) ($input['email'] ?? '')));
        if ($email !== '' && !Validator::isValidEmail($email)) $errors['email'] = 'Invalid email format';
        $password = (string) ($input['password'] ?? '');
        if ($password !== '' && strlen($password) < 6) $errors['password'] = 'Password must be at least 6 characters';
        if ($errors !== []) Response::error('Validation failed', 422, $errors);

        $repo = new UserRepository();
        if ($repo->findByEmail($email) !== null) Response::error('Email is already registered', 409);

        // Security rule: force 'student' role during public registration
        $userId = $repo->create([
            'full_name' => trim((string) $input['full_name']),
            'email' => $email,
            'password_hash' => password_hash($password, PASSWORD_BCRYPT),
            'role' => 'student',
            'student_id_number' => $input['student_id_number'] ?? null,
            'department' => $input['department'] ?? null,
            'phone' => $input['phone'] ?? null,
        ]);

        $token = bin2hex(random_bytes(32));
        $ttlHours = (int) Env::get('TOKEN_TTL_HOURS', '168');
        $expiresAt = date('Y-m-d H:i:s', time() + ($ttlHours * 3600));
        $repo->createSession($userId, $token, $expiresAt);

        Response::ok('Registration successful', [
            'token' => $token,
            'expires_at' => $expiresAt,
            'user' => $repo->findById($userId),
        ], 201);
    }

    public function login(array $context): void
    {
        $input = Response::readJsonBody();
        $errors = Validator::requireFields($input, ['email', 'password']);
        if ($errors !== []) Response::error('Validation failed', 422, $errors);

        $email = strtolower(trim((string) $input['email']));
        $password = (string) $input['password'];

        $repo = new UserRepository();
        $user = $repo->findByEmail($email);

        if ($user === null || !password_verify($password, $user['password_hash'])) {
            Response::error('Invalid email or password', 401);
        }
        if ((int) $user['is_active'] !== 1) {
            Response::error('Account is deactivated', 403);
        }

        $token = bin2hex(random_bytes(32));
        $ttlHours = (int) Env::get('TOKEN_TTL_HOURS', '168');
        $expiresAt = date('Y-m-d H:i:s', time() + ($ttlHours * 3600));
        $repo->createSession((int) $user['id'], $token, $expiresAt);

        unset($user['password_hash']);
        Response::ok('Login successful', [
            'token' => $token,
            'expires_at' => $expiresAt,
            'user' => $user,
        ]);
    }

    public function logout(array $context): void
    {
        if (!empty($context['token'])) {
            (new UserRepository())->revokeSession($context['token']);
        }
        Response::ok('Logged out successfully');
    }

import 'dart:convert';
import 'dart:io';

import 'package:flutter_secure_storage/flutter_secure_storage.dart';
import 'package:http/http.dart' as http;

import '../constants/api_constants.dart';
import '../errors/api_exception.dart';

class ApiClient {
  ApiClient({
    http.Client? httpClient,
    FlutterSecureStorage? secureStorage,
  })  : _httpClient = httpClient ?? http.Client(),
        _secureStorage = secureStorage ?? const FlutterSecureStorage();

  static const String _tokenKey = 'campus_auth_token';
  final http.Client _httpClient;
  final FlutterSecureStorage _secureStorage;

  Future<void> saveToken(String token) =>
      _secureStorage.write(key: _tokenKey, value: token);

  Future<String?> getToken() => _secureStorage.read(key: _tokenKey);

  Future<void> clearToken() => _secureStorage.delete(key: _tokenKey);

  Future<Map<String, dynamic>> get(String path, {Map<String, String>? queryParameters}) =>
      _send('GET', path, queryParameters: queryParameters);

  Future<Map<String, dynamic>> post(String path, {Map<String, dynamic>? body}) =>
      _send('POST', path, body: body);

  Future<Map<String, dynamic>> put(String path, {Map<String, dynamic>? body}) =>
      _send('PUT', path, body: body);

  Future<Map<String, dynamic>> delete(String path) =>
      _send('DELETE', path);

  Future<Map<String, dynamic>> _send(
    String method,
    String path, {
    Map<String, String>? queryParameters,
    Map<String, dynamic>? body,
  }) async {
    final uri = Uri.parse('${ApiConstants.baseUrl}$path').replace(
      queryParameters: queryParameters == null || queryParameters.isEmpty ? null : queryParameters,
    );

    final token = await getToken();
    final headers = <String, String>{
      'Content-Type': 'application/json',
      'Accept': 'application/json',
      if (token != null && token.isNotEmpty) 'Authorization': 'Bearer $token',
    };

    try {
      late final http.Response response;
      final encodedBody = body != null ? jsonEncode(body) : null;

      switch (method) {
        case 'GET':
          response = await _httpClient.get(uri, headers: headers).timeout(const Duration(seconds: 15));
          break;
        case 'POST':
          response = await _httpClient.post(uri, headers: headers, body: encodedBody).timeout(const Duration(seconds: 15));
          break;
        case 'PUT':
          response = await _httpClient.put(uri, headers: headers, body: encodedBody).timeout(const Duration(seconds: 15));
          break;
        case 'DELETE':
          response = await _httpClient.delete(uri, headers: headers).timeout(const Duration(seconds: 15));
          break;
        default:
          throw ApiException(message: 'Unsupported method: $method');
      }

      final decoded = _decodeJson(response.body);
      if (response.statusCode >= 200 && response.statusCode < 300 && decoded['success'] == true) {
        return decoded;
      }

      final rawErrors = decoded['errors'];
      final fieldErrors = <String, String>{};
      if (rawErrors is Map) {
        rawErrors.forEach((key, val) => fieldErrors[key.toString()] = val.toString());
      }

      throw ApiException(
        message: (decoded['message'] as String?) ?? 'Request failed',
        statusCode: response.statusCode,
        fieldErrors: fieldErrors,
      );
    } on SocketException {
      throw const ApiException(message: 'Unable to reach server. Check network and API URL.');
    }
  }

  Map<String, dynamic> _decodeJson(String body) {
    if (body.trim().isEmpty) return {'success': true, 'message': 'OK', 'data': null};
    final decoded = jsonDecode(body);
    if (decoded is Map<String, dynamic>) return decoded;
    throw const FormatException('Expected JSON object');
  }
}

      await loadMyRegistrations();
      return null;
    } on ApiException catch (e) {
      return e.message;
    } catch (_) {
      return 'Registration failed. Please try again.';
    } finally {
      state = state.copyWith(isSubmitting: false);
    }
  }

  Future<String?> cancelRegistration(int eventId) async {
    state = state.copyWith(isSubmitting: true);
    try {
      await _repository.cancel(eventId);
      await loadMyRegistrations();
      return null;
    } on ApiException catch (e) {
      return e.message;
    } finally {
      state = state.copyWith(isSubmitting: false);
    }
  }
}
